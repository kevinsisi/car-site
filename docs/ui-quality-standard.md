# Mita UI／UX 品質標準

此標準適用於後續所有前台與後台 UI 工作。使用者於 2026-10-06 明確要求，以 Awwwards、Webby Awards、FWA 獲獎作品所呈現的完成度為品質目標；這是持續追求的設計標準，不代表本站已獲獎、通過評審或取得認證。

## 必須遵守的交付方式

1. 先看實際畫面與元件上下文，確認品牌字體、色票、圓角、字階與主要／次要操作層級。沿用專案 token 和既有風格；局部修正不能無理由改成另一套視覺語言。
2. 先記錄可觀察的驗收條件與相關 OpenSpec，再實作；既有業務限制、權限及資料安全邊界必須保留。
3. 自我檢查真實瀏覽器渲染，針對裁切、對齊、密度、重複資訊、文案與操作回饋反覆修正。不能只用編譯成功或 DOM 存在宣稱 UI 完成。
4. 至少檢查 320、375、390、768、1024、1440 CSS px 寬度與相關橫豎向／縮放情境；畫面與互動要能適應內容，而非靠固定高度硬裁切。
5. 觸控目標至少 44×44 px；鍵盤焦點可見且不裁切，Tab 順序合理，選取狀態可辨識，展開／收合／關閉須有正確語意與焦點返回。尊重 reduced motion。
6. Fixed 區域須處理 safe-area，保留實際高度的頁底空間，避免遮住最後一筆內容、footer 和其他必要控制。
7. 同時驗證空、單項、多項、上限、長內容、缺圖片、移除、清空、刷新、前進／返回，以及儲存不可用等相關狀態。錯誤必須清楚顯示，不能讓視覺狀態與實際操作結果矛盾。
8. 交付包含最後來源版本／dirty 範圍、真渲染截圖與尺寸、操作結果、審查發現和修正、測試／build 證據及尚未驗證之處。高品質是具體驗證與迭代的結果，不能自行宣稱全面業務正確。

## 本次車輛比較驗收

- 卡片詳情與比較按鈕留足內距；選取前後尺寸不變，膠囊邊框／focus 完整。
- 清單使用固定比例縮圖、最多兩行且可及性完整的車名、必要年份、44px 移除按鈕；不重複車型與「比較清單」小字，不任意逐字斷行。
- 桌面緊湊等高、清晰主按鈕；手機常駐選取數和查看比較，按需展開清單、Escape／關閉返回焦點。
- 最多四台的既有上限一致套用卡片、清單和比較頁；拒絕第五台有明確回饋。
- 比較頁清除／移除最後一台不會被舊 localStorage 復活；返回列表、重新載入與分享 URL 的狀態一致。
- 圖像／測試資料使用已授權的本機或隔離資料；本機驗證與正式發布分別回報。
